[4.1] SQL CONVERSION & RECORD PROVENANCE

CSV → SQLITE

The source CSV contains 388 records and 14 columns. After trimming whitespace and standardizing occupation labels, 103 full-row matches are excluded, leaving 285 retained records. This follows Assignment 3. The unnamed final column duplicates Output in every source record and is omitted.

Each database ID identifies a retained record, not a verified unique person. Without respondent IDs, identical source rows could represent different people. The original CSV is included unchanged for comparison. No missing-value imputation or outlier deletion was required by this conversion.

[4.2] SQL TABLE STRUCTURE & JOIN RELATIONSHIP

income_levels

5 rows · Primary key: income_level_id

Category label, display order, and INR currency code.

respondents

285 rows · Primary key: respondent_id

income_level_id references income_levels.income_level_id. Each income category can relate to many respondent records.

This lookup table gives the JOIN a real purpose: it attaches readable income labels and category order without repeating that metadata in every respondent record. Primary keys, foreign keys, and CHECK constraints validate the loaded structure.

SHOW EXECUTABLE SCHEMA
PRAGMA foreign_keys = ON;

CREATE TABLE income_levels (
    income_level_id INTEGER PRIMARY KEY,
    income_label TEXT NOT NULL UNIQUE,
    sort_order INTEGER NOT NULL UNIQUE,
    currency_code TEXT NOT NULL CHECK (currency_code = 'INR')
);

CREATE TABLE respondents (
    respondent_id INTEGER PRIMARY KEY,
    source_csv_row INTEGER NOT NULL UNIQUE,
    age INTEGER NOT NULL CHECK (age BETWEEN 0 AND 120),
    gender TEXT NOT NULL CHECK (gender IN ('Male','Female')),
    marital_status TEXT NOT NULL
        CHECK (marital_status IN ('Single','Married','Prefer not to say')),
    occupation TEXT NOT NULL
        CHECK (occupation IN ('Student','Employee','Self Employed','Housewife')),
    income_level_id INTEGER NOT NULL REFERENCES income_levels(income_level_id),
    education TEXT NOT NULL,
    family_size INTEGER NOT NULL CHECK (family_size BETWEEN 1 AND 30),
    customer_type TEXT NOT NULL
        CHECK (customer_type IN ('New','Regular','Frequent')),
    latitude REAL NOT NULL CHECK (latitude BETWEEN -90 AND 90),
    longitude REAL NOT NULL CHECK (longitude BETWEEN -180 AND 180),
    pin_code TEXT NOT NULL CHECK (length(pin_code) = 6),
    ordered_yes INTEGER NOT NULL CHECK (ordered_yes IN (0,1)),
    feedback_positive INTEGER NOT NULL CHECK (feedback_positive IN (0,1))
);

SQL dialect: SQLite 3. The queries use common SQL syntax; the database file and PRAGMA commands are SQLite-specific. INTEGER, REAL, and TEXT are SQLite storage affinities.

Q06 · Compare marital-status groups

GROUP BY

Q07 · Keep occupation groups with sufficient records

Q08 · Join income labels to respondent records

JOIN
SELECT i.income_label,
       COUNT(*) AS records,
       SUM(r.ordered_yes) AS yes_records,
       ROUND(100.0 * AVG(r.ordered_yes), 2) AS yes_rate_pct
FROM respondents AS r
JOIN income_levels AS i
  ON r.income_level_id = i.income_level_id
GROUP BY i.income_level_id, i.income_label, i.sort_order
ORDER BY i.sort_order;
